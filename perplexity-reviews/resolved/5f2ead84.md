# Code Review: 5f2ead84

> fix: route review IPC to correct provider (chatgpt vs perplexity)

## Summary
This commit refactors the Proxima review IPC logic to dynamically route requests to either **ChatGPT** or **Perplexity** based on the `REVIEW_MODEL` prefix. Previously, `queryPerplexity()` was hardcoded to send `provider: 'perplexity'` and always used `modelPreference`. Now, `queryAI(message, model, provider)` builds the payload dynamically: ChatGPT receives `{ message, model }` while Perplexity receives `{ message, modelPreference, deepSearch: false }`. The provider is auto-resolved via `resolveProvider()` and is included in the review frontmatter. This allows switching providers simply by changing `REVIEW_MODEL`. I verified the payload structures align with typical IPC conventions and Proxima Agent Hub expectations.

## Security & Performance

- **Performance:** Single socket connection with large 10-min timeout may block multiple parallel requests; consider connection pooling or async queue if scaling (L133-L135).  
- **Scalability:** Dynamic provider switching is efficient, reduces duplication, and isolates provider-specific payload logic.  

## Overall Score: 9/10
The refactor is clean, reduces hardcoding, and improves maintainability. Minor improvements around prefix handling, timeout configurability, and error messaging could increase robustness.

## Recommendations

2. Make IPC timeout configurable via env variable to avoid blocking long-running or stalled requests (L133).  
3. Validate `model` strings sent to Perplexity to prevent mismatched identifiers (L138-L147).  
4. Standardize error messages to avoid leaking provider identifiers in exceptions (L175-L180).  
5. Consider async queuing or socket pooling if multiple reviews are submitted concurrently (general IPC section L130+).  

This commit is otherwise well-structured and aligns with IPC protocol expectations.
