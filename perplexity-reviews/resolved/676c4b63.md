# Code Review: 676c4b63

> fix: forward data.model in sendMessage IPC options

## Summary
This commit fixes a mismatch in IPC `sendMessage` options in `electron/main-v2.cjs`. Previously, only `data.modelPreference` was forwarded, which worked for Perplexity but caused **ChatGPT** to receive an undefined model. The commit adds `model: data.model` to `sendOptions`, ensuring ChatGPT reads the intended model (e.g., `gpt-5-5-thinking`). I verified that the ChatGPT engine typically expects `options.model` while Perplexity uses `modelPreference`, so this aligns with the correct IPC contract.

## Issues & Fixes
| File:Line | Severity | Issue | Fix |
|------------|----------|-------|------|
| electron/main-v2.cjs:L510 | ⚠️ | ChatGPT engine may fail if `data.model` is undefined or null. | Add a null/undefined check: `model: data.model || defaultModel` to ensure a fallback is always sent. |
| electron/main-v2.cjs:L509-L510 | ⚠️ | Logging `sendOptions` with `console.error` may expose sensitive info in production. | Use `console.debug` or sanitize sensitive fields before logging. |
