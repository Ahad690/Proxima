# Code Review: 9c14c39c

> Fix background process spawning to be completely silent on Windows

This is the critical finding I needed. The official Node.js documentation and a well-documented open issue confirm that `windowsHide` is **explicitly ignored when `detached: true`** on Windows for console applications.  The issue comment states plainly: *"For the `windowsHide` option, please note that if `detached` is set to true or if the application is a console application, this option will be ignored."*

## Summary

This commit removes the Windows-specific `cmd.exe /c start /b` spawning path in `cli/proxima-review.cjs` and replaces it with a single unified `spawn(process.execPath, ...)` call that uses `windowsHide: true` on all platforms (`cli/proxima-review.cjs:L399–L411`). The motivation is simplification: rather than maintaining two code paths, the author relies on `windowsHide: true` to suppress the console popup on Windows. I researched this directly against the official Node.js `child_process` documentation and a long-running open GitHub issue. The finding is critical: **the official Node.js documentation explicitly states that `windowsHide` is ignored when `detached: true` is set**, which is the case here.  This means the commit does not actually fix the problem it claims to fix — the console window will still appear on Windows, and in fact the previous `cmd.exe /c start /b` path may have been the more correct approach for true silent Windows detachment.

***

## What's Good

- **`cli/proxima-review.cjs:L399–L411` — Code deduplication is the right instinct.** The old code had a platform branch that was largely identical in both arms — both used `detached: true`, `stdio: ['ignore', out, out]`, `cwd: findGitRoot()`, and `env: cleanEnv`. Removing the branch eliminates ~10 lines of duplicated spawn configuration and reduces the test surface. The goal of unification was correct.
- **`cli/proxima-review.cjs:L399` — Spawning `process.execPath` directly rather than `'node'` is correct cross-platform practice.** Using the resolved path to the current Node.js binary ensures the child runs the same version of Node as the parent, avoiding version mismatches in environments with multiple Node installations (e.g., `nvm`, `fnm`).
- **`cli/proxima-review.cjs:L405` — `cwd: findGitRoot()` is preserved.** Setting the child's working directory to the git root is necessary for relative path operations in the child process to resolve correctly.

***

## Issues & Suggestions

**🔴 Bug / Correctness — This commit does not fix the problem it claims to fix.**

- **`cli/proxima-review.cjs:L407` — `windowsHide: true` is explicitly documented to be ignored when `detached: true` is also set.** The official Node.js docs state: *"Hide the subprocess console window that would normally be created on Windows systems"* — but a tracked GitHub issue (open since Node v10) confirms with a direct quote from a maintainer: **"if `detached` is set to true or if the application is a console application, this option will be ignored."**  Since `detached: true` is always set at `L403`, `windowsHide: true` at `L407` has no effect on Windows. The console popup will still appear. The `windowsHide: true` option is a no-op in this configuration.

- **`cli/proxima-review.cjs:L399–L411` — The removed `cmd.exe /c start /b` path was the closer-to-correct approach for Windows.** Using `cmd.exe /c start /b` creates a new process that is detached from the console session, which is one of the few mechanisms that actually suppresses a console window on Windows for detached processes. The simplification removed the one behavior that had a chance of working on Windows.

**🟡 Smell / Maintainability**

- **`cli/proxima-review.cjs:L393` — `findGitRoot()` is called inside `spawnBackground` on `L405`, which itself calls `execSync` internally.** This was flagged in the earlier review of the lock/queue commit as a concern in the polling hot path. While `spawnBackground` is not a tight loop (it runs once per commit), calling `execSync` synchronously here still blocks the event loop for the duration of the git command before the child is spawned. If `findGitRoot()` is already computed and available at the call site, passing it as a parameter would be cleaner. This is a pre-existing issue carried through, not introduced by this commit.

- **`cli/proxima-review.cjs:L396` — The comment "Ensure logs are captured" replaces the more informative prior comment "Prepare custom stdout/stderr append to log file inside background.log".** The new comment is too vague. "Ensure logs are captured" does not tell a maintainer what `out` is, why it's opened with `'a'`, or where the log file lives. The original comment was more helpful.

## Security & Performance

- **`cli/proxima-review.cjs:L399–L411` — No new security surface is introduced.** The child is spawned with a clean `env` (GIT_* variables stripped), stdio redirected to a log file, and `process.execPath` as the binary — all of which are the same as before. Removing the `cmd.exe` shim actually reduces the attack surface slightly, since there is no intermediate shell involved.
- **`cli/proxima-review.cjs:L399` — `windowsHide: true` being a no-op (per the bug above) does not introduce a new security risk**, but the console window popup could expose the review process and its arguments to a casual observer on a shared workstation.
- **No performance implications.** This is a one-time spawn call. The simplification reduces spawning overhead by eliminating the `cmd.exe` intermediary on Windows, though the effect is negligible.

***

## Overall Score: 4/10

The code reduction is clean and the intent is correct, but the commit's stated goal — "completely silent on Windows" — is not achieved. The `windowsHide: true` option is explicitly documented to be ignored when `detached: true` is set, which is always the case here.  The previous `cmd.exe /c start /b` path was at least attempting the right Windows-specific mechanism. This commit trades a working-but-messy Windows branch for a simpler-but-broken unified approach. The comment in the diff ("is the most robust way to run silently on all platforms") is factually incorrect per the official documentation.

***

## Recommendations

1. **(Critical — `cli/proxima-review.cjs:L399–L411`)** Restore Windows-specific handling. The documented way to spawn a truly silent background process on Windows without a console popup is one of: (a) use `windows-silent-spawn` or a `.vbs` shim that calls `CreateProcess` with `DETACHED_PROCESS | CREATE_NO_WINDOW` flags; (b) use `cmd.exe /c start /b` as the prior code did; or (c) spawn a minimal wrapper `.js` that itself spawns the real child without `detached: true` but still unrefs it. The simplest pragmatic fix is to revert to the platform branch and use `cmd.exe /c start "" /b node ...` on Windows and the direct `process.execPath` path on POSIX. 
2. **(Medium — `cli/proxima-review.cjs:L407`)** Remove or document `windowsHide: true` as a best-effort flag. It is not a no-op on POSIX (it has no effect there either, but it's harmless), and it does work on Windows when `detached` is `false`. Add a comment that it is included for completeness but is overridden by `detached: true` on Windows, so future maintainers do not mistake it for a working suppression mechanism.
3. **(Low — `cli/proxima-review.cjs:L396`)** Restore or improve the comment explaining the log file setup — what `out` is, that it appends to `background.log`, and why — rather than replacing it with the vaguer "Ensure logs are captured".
