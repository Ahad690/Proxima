# Code Review: 51b6ecc9

> Add Deep Research quota-aware routing with fallbacks

This commit (`51b6ecc9`) was already reviewed earlier in this conversation. Rather than repeating the same analysis, here is the full review for your records — incorporating everything identified the first time, presented as a clean standalone document.

***

## Summary

This commit introduces quota-aware routing for Deep Research mode in `perplexity-engine.js`. It adds `_checkDeepResearchQuota()` to pre-flight the `/rest/rate-limit/status` endpoint before deciding whether to route a query as `agentic_research` or fall back to `copilot` mode. It wires in dynamic `supported_block_use_cases`, Deep Research-specific API params (`extended_context`, `always_search_override`, `search_mode`, etc.), and removes the old `deepSearchCount` counter from the MCP tools in `mcp-server-v3.js`. The MCP changes are minor cleanups — splitting one-liner `toolResponse(await ...)` calls into two-line `const result = await ...; return toolResponse(result)` patterns and minor description wording tweaks. The intent is sound but the implementation is not production-ready as submitted.

***

## What's Good

- **Graceful fallback design**: `_checkDeepResearchQuota()` returns `{ available: true, remaining: -1 }` on both network failure and unexpected response shapes, ensuring Deep Research requests degrade to Pro Search rather than crashing the call.
- **Separation of concerns**: Extracting quota-checking into its own named function rather than inlining it in `send()` is the right architectural choice — it is independently testable and readable.
- **Dynamic `supported_block_use_cases`**: Conditionally pushing `workflow_steps` and `background_agents` only for `agentic_research` mode is correct and semantically clean.
- **Replacing the counter with a live API check**: A live quota check from the API is strictly more correct than a manual local counter, which could desync after app restarts, crashes, or external usage.
- **MCP result variable refactor**: Splitting `toolResponse(await p.instance.chat(...))` into `const result = await ...; return toolResponse(result)` is a minor but valid readability improvement that also creates a future insertion point for logging or transformation.

***

## Issues & Suggestions

- **`var` throughout an async/modern codebase** (`perplexity-engine.js`, multiple lines): `_checkDeepResearchQuota`, `send()`, and the new param-building block all use `var` (`var res`, `var data`, `var agenticData`, `var quota`, `var params`, `var isDeepSearch`, `var finalMode`, `var supportedBlocks`). The MCP file uses `const`/`let` consistently. In async functions, `var`'s function-scoped hoisting is especially error-prone. **Replace every `var` with `const` or `let`.**

- **Indentation regression on `var params`** (`perplexity-engine.js`, line ~307): The `var params = {` block has zero indentation while the surrounding code is indented. The `version: '2.18'` key-value pair inside the object is also flush against column 0 while all other keys are indented. This is a whitespace bug likely caused by a careless manual edit. Fix indentation throughout.

- **Comment indentation lost in `mcp-server-v3.js`** (line ~562): The `// If using Perplexity...` comment lost its indentation and sits at column 0. Minor, but reveals the diff was applied sloppily.

- **`quota.remaining === 0` edge case is over-blocking**: The condition `quota.available === false || quota.remaining === 0` will block Deep Research when `remaining` is `0`. However, the fallback also sets `remaining: 0` when `remaining_detail` is absent. If the API returns a shape where `agenticData` exists but `remaining_detail` is null, `remaining` becomes `0` and the gate incorrectly blocks an available-but-uncounted quota. Separate the two conditions:
  ```js
  if (!quota.available) { /* block */ }
  else if (quota.remaining !== -1 && quota.remaining === 0) { /* block */ }
  ```

- **No timeout on the quota `fetch`**: If `https://www.perplexity.ai/rest/rate-limit/status` hangs, the entire `send()` call will hang indefinitely. Add an `AbortController` with a short timeout (e.g., 3 seconds):
  ```js
  const controller = new AbortController();
  const timer = setTimeout(() => controller.abort(), 3000);
  const res = await fetch(url, { signal: controller.signal, ... });
  clearTimeout(timer);
  ```

- **Raw SSE logging left in production path** (`perplexity-engine.js`, line ~149): `console.log('[RAW SSE]', data.substring(0, 500))` fires on **every single SSE message** for every query — not just Deep Research queries. This produces massive log output and could expose partial user response content in logs. **Remove or gate behind a debug flag before merging.**

- **Block-type logging left in production path** (line ~163): `console.log('[Perplexity block]', Object.keys(block))` has the same problem. Remove or flag.

- **`STEP N:` comments throughout production code**: Comments like `// STEP 3:`, `// STEP 4:`, `// STEP 5:`, `// STEP 6:`, `// STEP 7:`, `// STEP 8:` are development-time breadcrumbs that have no place in a committed diff. They signal the code is still in an exploratory state. **Remove all of them.**

- **No unit or integration tests added**: A quota-aware routing change of this magnitude warrants at minimum mock tests of `_checkDeepResearchQuota()` covering: success with quota available, `available: false`, `remaining === 0`, missing `agenticData`, network error, and timeout. None were added.

***

## Security & Performance

- **`credentials: 'include'` on the rate-limit endpoint**: Presumably intentional (session-based auth), but confirm this endpoint does not return PII or quota details that should not be accessible from the renderer process. If running in the Electron renderer, session cookies are correctly in scope, but ensure the endpoint is only called when the user session is active.

- **Duplicated URL in `x-perplexity-request-endpoint` header**: This custom header mirrors the fetch URL. If one is updated but not the other, a mismatched value is silently sent. Extract to a shared constant:
  ```js
  const RATE_LIMIT_URL = 'https://www.perplexity.ai/rest/rate-limit/status?version=2.18&source=default';
  fetch(RATE_LIMIT_URL, { headers: { 'x-perplexity-request-endpoint': RATE_LIMIT_URL, ... } });
  ```

- **Additional latency on every Deep Research call**: Every `deepSearch: true` request now makes a blocking pre-flight HTTP round-trip before the actual query. Consider **caching the quota response** for a short TTL (e.g., 60 seconds) in memory so repeated requests don't each pay this cost. At typical API latency of 200–500ms, this is directly user-visible.

- **`console.log` of `quota.remaining` leaks quota state to renderer logs**: If logs are written to file or sent to a remote service, this may be undesirable. Low-priority but worth noting.

- **5-second `setTimeout` in MCP tools** (`await new Promise(r => setTimeout(r, 5000))`): Pre-existing but worth flagging — a hard-coded 5-second delay before every Perplexity call with no back-off, jitter, or queue is fragile. Consider a proper request serialization queue.

***

## Overall Score: 5.5/10

The core idea is correct and well-structured, but the commit is not production-ready. It contains debug logging active in every SSE hot path, development-stage `STEP N` comments, inconsistent `var` usage and indentation regressions, a latency concern with no caching mitigation, and an edge case in the quota guard logic. The MCP changes are clean. With the issues above addressed, this would comfortably be a 7.5–8/10.

***

## Recommendations

Prioritized from most to least critical:

1. **Remove or gate the raw SSE and block-type `console.log` calls immediately** — they fire on every query for every user and will flood logs with potentially sensitive response data.
2. **Add an `AbortController` timeout** (3s) to `_checkDeepResearchQuota()` to prevent `send()` from hanging on a slow rate-limit endpoint.
3. **Cache the quota response with a 60-second in-memory TTL** to eliminate the blocking pre-flight round-trip on every Deep Research call.
4. **Fix the `quota.remaining === 0` guard** to avoid blocking requests when `remaining_detail` is absent by distinguishing `0 remaining` from "count unknown."
5. **Replace all `var` with `const`/`let`** and fix the indentation regressions on `var params` and `version: '2.18'`.
6. **Remove all `STEP N:` comments** — they are development scaffolding, not documentation.
7. **Extract the rate-limit URL into a named constant** shared between the `fetch` call and the `x-perplexity-request-endpoint` header value.
8. **Add tests for `_checkDeepResearchQuota()`** covering the five key scenarios: quota available, `available: false`, `remaining === 0`, missing `agenticData`, and network/timeout failure.
