# Code Review: 3d894744

> Enhance pre-push hook background review spawning and unsetting git environment variables

## Summary

This commit improves the `spawnBackground` function in `proxima-review.cjs` and the generated shell hook in `install-hooks.cjs`. The key changes are: stripping `GIT_*` environment variables from the background child process (preventing git command interference), routing background process stdout/stderr into a persistent log file, adding Windows compatibility via `cmd.exe /c start /b`, introducing a `logToFile` utility so background-mode messages persist, fixing a new-branch `git rev-list` bug with `-n 1`, and hardcoding the Node.js executable path in the generated shell hook instead of relying on ambient `node` in `$PATH`.

***

## What's Good

- **`GIT_*` env stripping is the right fix.** Git sets variables like `GIT_DIR`, `GIT_INDEX_FILE`, and `GIT_WORK_TREE` in hook environments. These break child `git` invocations. The allowlist-by-exclusion pattern (`!key.startsWith('GIT_')`) is a well-known, battle-tested mitigation.
- **`PROXIMA_BACKGROUND_REVIEW=1` flag is clean.** Using an env flag to toggle dual logging (`console.log` + `logToFile`) rather than threading a boolean argument through the call stack is idiomatic and low-coupling.
- **`logToFile` silent catch `{}` is acceptable here.** Logging must never crash the reviewer; swallowing errors on a non-critical diagnostic path is justified. Good judgment call.
- **Hardcoding `process.execPath` in the hook** (`NODE_EXE`) avoids PATH resolution failures in environments like VS Code's Git integration or CI runners, where `node` may not be on `$PATH` for shell hooks. This is a meaningful reliability improvement.
- **Windows `windowsHide: true`** prevents a terminal window flashing on Windows during background spawn — a polished UX detail.
- **`-n 1` fix for new branches** (`remoteSha === NULL_SHA`) is a real bug fix. Previously `git rev-list --reverse <sha>` on a new branch would walk the entire commit history, potentially triggering hundreds of reviews. Limiting to 1 is correct for the "only review the tip" intent.

***

## Issues & Suggestions

- **`cmd.exe /c start /b` doesn't detach cleanly on all Windows versions.** The `start /b` command runs in the same console window and is not equivalent to Unix `detached: true`. The process may still be tied to the parent's console session. A more robust Windows approach is to use `spawn('node', [...], { detached: true, ... })` directly — the `cmd.exe` wrapper adds unnecessary complexity without guaranteed detachment.

  ```js
  // Simpler and more reliable on Windows too:
  const child = spawn(process.execPath, [__filename, sha], {
      detached: true,
      stdio: ['ignore', out, out],
      cwd: findGitRoot(),
      env: cleanEnv,
      windowsHide: true
  });
  ```

- **`fs.openSync` file descriptor is never closed (`out` leaks).** After `child.unref()`, the `out` fd remains open in the parent process. On high-frequency pushes this accumulates. You should close it after spawn:

  ```js
  child.unref();
  fs.closeSync(out); // ← add this
  ```

- **`logToFile` duplicates directory-creation logic.** `REVIEW_DIR` existence is checked in at least three places now (`runReview`, `spawnBackground`, `logToFile`). Extract a `ensureReviewDir()` helper called once at startup or lazily, not scattered across functions.

- **`log` function in `runReview` strips ANSI when writing to file.** `logToFile` writes raw strings including ANSI escape codes (e.g. `cyan(...)`, `red(...)`). Log files will contain garbled color codes like `\u001b[36m🤖\u001b[0m`. Strip colors before writing to file:

  ```js
  const stripAnsi = (s) => s.replace(/\x1b\[[0-9;]*m/g, '');
  fs.appendFileSync(logFile, `[${new Date().toISOString()}] ${stripAnsi(msg)}\n`, 'utf8');
  ```

- **`-n 1` for new branches may miss multi-commit initial pushes.** If a developer creates a branch and pushes 5 commits at once, only HEAD is reviewed. This may be intentional, but it's worth a comment clarifying the decision:

  ```js
  // New branch: review only HEAD to avoid reviewing entire repo history
  ? '-n 1 ' + localSha
  ```

- **`install-hooks.cjs` escaping inconsistency.** The fix to `\$REVIEW_SCRIPT` and `\$NODE_EXE` in the generated shell script is correct (they must not be interpolated at hook-generation time), but the surrounding variables like `"$REVIEW_SCRIPT"` (non-escaped) and `"${unixPath}"` (JS template literal) in the same heredoc create a subtle mental model mismatch. Consider adding a comment block at the top of `buildHookScript` clarifying which variables are JS-interpolated vs. shell-runtime.

***

## Security & Performance

- **Environment inheritance is conservative but potentially leaky.** The `cleanEnv` strips `GIT_*` but passes everything else — including `npm_*`, `NODE_*`, credentials in env vars, CI secrets, etc. — to an unmanaged detached background process. For a tool installed on developer machines this is likely acceptable, but worth noting in documentation: background processes inherit the full shell environment minus Git internals.
- **Log file has no rotation or size cap.** `background.log` is append-only with no truncation. On active repos over time this file will grow unboundedly. A simple size-check-and-rotate or a max-lines cap would prevent disk issues.
- **`fs.openSync` before `spawn` is a TOCTOU-safe pattern**, which is good — the fd is opened before the child is created, so the child always inherits a valid write target. This is the correct ordering.
- **No sanitization of `sha` passed to `cmd.exe` args on Windows.** While SHAs are hex-only and safe in practice, if `sha` ever originates from user-controlled input (e.g., branch names), the Windows `cmd.exe` invocation path is a command-injection surface. Low risk currently, but worth a `sha.match(/^[0-9a-f]+$/)` guard.

***

## Overall Score: 7.5/10

This is a solid, practical commit that fixes a real bug (GIT_* env pollution) and several reliability gaps (PATH, new-branch rev-list, Windows UX). The implementation is readable and intentional. The score is held back by the fd leak, the ANSI codes in log files, and the over-engineered Windows spawn path that doesn't fully deliver on its promise.

***

## Recommendations

1. **Fix the `fs.openSync` fd leak** — add `fs.closeSync(out)` immediately after `child.unref()`. This is the only functional bug introduced.
2. **Strip ANSI escape codes in `logToFile`** — log files with raw color codes are unusable in most editors and `grep` workflows.
3. **Simplify Windows spawning** — drop the `cmd.exe /c start /b` wrapper and use `spawn(process.execPath, ...)` with `detached: true` directly; it works on Windows too.
4. **Add log rotation** — even a simple "truncate if > 1MB" guard on `background.log` prevents a long-term disk leak.
5. **Consolidate `ensureReviewDir()`** — deduplicate the three `existsSync/mkdirSync` patterns into one shared call.
6. **Document the `-n 1` new-branch behavior** — clarify in a comment whether reviewing only HEAD on new branches is by design.
